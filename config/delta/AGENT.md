# Global Instructions

## 作業の進め方

- 日本語で簡潔に報告する。
- 各リポジトリの AGENTS.md と、依頼されたタスクの要件・設計・計画を読む。
- 着手前に作業ディレクトリ、branch、git status を確認する。
- 不確かなことは推測せず確認する。設計や前提の変更が必要なら、実装を広げる前に相談する。
- 依頼されていないリファクタや機能追加をしない。
- 利用可能な Superpowers の手順に従う。
- 外部サービスの操作は専用 MCP を優先する。

## ブランチと作業場所

- feature branch の作成も自分で行う。
- 指定された base branch を fetch し、必要な先行変更が取り込まれていることを確認する。起点の SHA を記録して専用ブランチを作成する。
- base branch の指定がなければ、リポジトリの指示を確認し、判断できなければ質問する。
- main / master / base branch 上で直接編集しない。
- 指定された checkout / worktree を使う。過去の作業場所を推測して使わない。
- 未コミット変更を移動・破棄・自動 stash しない。作業が混在する場合は独立 worktree を使うか相談する。
- 同名ブランチや既存 PR がある場合は内容を確認し、強制更新・削除・重複作成をしない。

## 実装と検証

- 挙動変更は、失敗するテスト → 最小実装 → 検証の順で進める。
- 既存の共通処理と契約を使い、重複実装や将来のための抽象化を増やさない。
- ツール・依存の管理方法と検証コマンドはリポジトリの規約に従う。
- テストには一時生成した合成データを使い、ユーザー素材・秘密情報を fixture にしない。
- 自動テスト、実環境の確認、人による受け入れを区別する。skip・未実行・承認待ちを成功扱いにしない。
- 完了前に必要な検証、最終レビュー、git diff --check を行う。

## Commit と Draft PR

- 通常の開発タスクでは、意味のある区切りで適切な粒度の commit を行う。commit ごとの確認は不要。
- 実装・テスト・文書など、レビューと取り消しがしやすい意味のある区切りで commit する。機械的なファイル単位や、不完全な状態で細分化しない。
- commit 前に対象 diff と検証結果を確認する。他の作業の変更を stage しない。
- commit 規約と template に従う。規約がなければ、件名は template の絵文字と英語の動詞で始める。
- Delta review で approve が付いたら、必要な検証と最終レビューを行ったうえで feature branch を push する。
- approve 時点で該当する draft PR がなければ、指定された base branch 向けに作成する。すでにあればその PR に変更を push する。
- 同じ head / base の PR があれば重複作成しない。ready 化・merge はしない。
- --no-verify と force push は使わない。
- repo に変更がなければ、空 commit・空 PR を作らず理由を報告する。

## PR の内容

- PR template があれば従う。
- template がなければ、関連 issue → why → what → how の順で書く。
- 関連 issue がなければ「関連 issue なし」と書く。
- title は何が変わるかを表す。
- 経緯を知らない読者向けに、問題、変更後の挙動、変わらないことを説明する。
- 検証結果、未検証事項、依存関係、単独マージ可否を記載する。
- bold / italic / underline は使わない。コード span は使用可。
- issue tracker を操作できなくても、渡された issue URL を本文に含める。

## 承認が必要な操作

- インフラ・CI/CD設定の変更、実素材の公開・upload、削除、依存の削除・ダウングレード、system package の導入は事前に確認する。
- PR 作成以外の外部投稿と issue tracker の更新は、明示的に依頼された場合だけ行う。
- 承認を求める前に、変更対象・影響・確認方法を具体化する。
- すでに得た承認は再確認しない。commit・push・draft PR の許可を、実公開やインフラ変更の許可とみなさない。

## 完了報告

- 検証結果、未解決・未検証・承認待ち事項、draft PR の URL を簡潔に報告する。
- 他エージェントへ引き継ぐ場合は、作業場所、branch、起点と現在の commit、残る作業を示す。
- issue tracker に転記できる短い報告文を添える。
